# 再生金属来料与料堆追溯平台

把**逐车称重、样品品位、混料去向和供应商应付款**连接到同一条可核对的链路，让采购、料场与财务
核对的是*同一批材料*，而不是各自维护互不相认的总数。

- 后端：Go 1.26（仅标准库 `net/http` 路由 + `pgx` 驱动 PostgreSQL）
- 前端：Vue 3 + Vite
- 数据库：PostgreSQL 18
- 不连接任何真实仪器：磅秤报文、样品档案、转移单都以**项目自带样例文件**的形式录入

---

## 一、它解决什么

| 现场问题 | 平台做法 |
| --- | --- |
| 同一供应商一天送几车，化验单只写公司+日期，无法确定属于哪车 | 每车建立稳定批次号（`B-YYYYMMDD-nnn`），封样**必须**绑定车次与取样位置；缺归属的化验直接拒收，不按日期自动分配 |
| 毛重/皮重/复称混在一起，不知道采用哪次 | 每次称重独立留痕（磅单号唯一），采用记录单独一条：保留原值，写明采用依据，重采产生新版本 |
| 按供应商日均品位让好坏料抵消 | 品位按**车次**计算，不按供应商汇总 |
| 按当前堆位名追溯，拆分后丢失来源 | 追溯按**库存状态节点 + 来源关系**，每次动作生成新节点；料回到同一物理堆位也是合法的新节点 |
| 干基/湿基混用、重复扣水 | 合同登记独立公式与各比例的基准；一次扣水得干重，干重再扣已单列杂物；另一基准必须登记为独立公式 |
| 缺参数仍然付款 | 缺采用称次、缺采用化验、缺批准等级时一律暂停付款并给出原因 |
| 复检/复称直接改可付款状态 | 复检不会自己改付款；财务先看新旧净重/金属量/应付差额，再批准新版本；原单永久保留 |
| 隔离料通过混料“洗白” | 只有已批准且非隔离的等级可进可用堆；任何含隔离来源的入库/合堆到可用堆都被拒绝 |
| 超库存、关联成环、凭空增加 | 转移单先锁定所用余额，转出 = 转入 + 明确损耗必须精确成立；每个转入方向都新建节点，因此不会误判环 |
| 两人同时抢同一余量 | 行锁 + 锁后重查余额，只有一人成功，另一人被“禁止超库存”阻断 |
| 水分减少被当成金属流失 | 干燥损耗只减重量、不减金属；加工损耗同时按比例减重与减金属，分别计量 |
| 只核对总额相等 | 逐车守恒报表：入库 = 在库 + 投炉在产 + 发运 + 加工损耗 + 干燥损耗（重量与金属各自成立，尾差为 0） |
| 某车出问题，不知道还有哪些料受影响、哪些已追不回 | 从问题车出发沿**带数量的转移关系**传播，按存量/已耗用/在制/已发分别列出；已发与在制明确标注“无法追回” |
| 混堆后分几次投炉，简单递归把汇合处同一来源算两遍 | 汇合节点按来源流量归并，节点影响量不超过其历史接收量，处置合计与源车接收量核对 |
| 分拣记录不全时被迫给出一个“精确”数 | 来源比例未知的转移边给出受影响量**上下界**，结果显式标记为区间，不伪装精确 |
| 只隔离当前库存，漏掉已投料和发货 | 隔离只阻断在库批次的新领料；已发/在制保留并继续追查下游，不回滚成料还在场 |
| 隔离审批基于过期排查 / 并发转移冲突 | 排查快照带库存序号；期间又发生转移则旧结论拒绝批准。领料与隔离在同一事务里按行锁检查物料状态 |
| 解除隔离只复核一部分、多起事件重叠 | 复核只覆盖部分则剩余继续阻断；同一批次被多起事件持有必须全部复核才释放 |

## 五、样例数据里的完整故事

`cmd/seed` 写入（全部真实执行于数据库）：

1. **华东再生金属**同一天送来 3 车废铜，批次 `B-20261110-001/002/003`；每车独立封样并绑定取样位置（车厢前部/中部/后部）。
2. 第 2 车**复称**：两次毛重，第二次采用；原值与“地磅零点校正单”的依据都保留。
3. 三车各自化验，质量确认采用；第 3 车杂质 6.2%，批准为隔离等级 `CU-DIRTY`。
4. 第 1、2 车入库到接收区，第 3 车入库到隔离堆。
5. 第 1、2 车先各生成 **应付 v1** 并批准。
6. **合堆**：两车料以均匀混合方式进入可用堆 #1。
7. **拆分**：拆出一半投炉，声明 **0.6% 干燥损耗**（只减重、不减金属）。
8. **隔离料尝试混入可用堆 → 被拒绝**（HTTP 409）。
9. **复检下调**：化验员对第 1 车同一封样提交新版化验（金属 62.5%→61.2%、杂物 1.1%→1.65%），
   质量采用后 `reassay` **沿来源关系**把可用堆、投炉、发运各节点按金属占比调整（投炉在产不会被撤销）。
10. **应付新版**：第 1 车 v2 生成并批准；v1 保留为 `superseded`，差额写入调整台账
    （−¥26,031.33，即 −2,603,133 分）。
11. **两人争用同一余量**：操作员甲把可用堆剩余量整批出库；操作员乙对同一余额的申请**被阻断**。
12. **重放**：再次提交 `MX-2601-001` 不移动任何材料（幂等）。
13. **质量排查处置（新增）**：第 4 车（问题车，杂质偏高）与第 5 车（好料）均匀混堆 →
    混堆拆成 A、B 两支（**两支来源分拣记录都不完整**，`mode=unknown`）→ A、B 两支 3/4 **重新汇合**
    到同一可用堆（两条路径汇合的菱形）→ 汇合堆 2/5 投炉（在制）、3/10 出库（已发）。
    对第 4 车声明质量事件 `QEV-2601-001`（风险范围 2.0%–3.2%），生成排查快照 `#1` 并申请隔离单
    `ISO-2601-001`。排查结果：存量 2,850–8,550 kg、在制 1,800–5,400 kg、已发 1,350–4,050 kg，
    合计下界 6,000 kg、上界 18,000 kg（= 源车接收量，汇合未重复计数）。

## 七A、质量排查与隔离处置（新增）

页面：<http://localhost:8080/quality>（质量 / 管理员账号 `quality` / `quality123`）。

### 排查：沿带数量的转移关系传播

不是“沿来源递归累加”。每个库存节点记录其**历史接收量**，排查沿每条带数量的转移边按实际流量传播：

- **汇合节点按来源流量归并**：多条入边分别携带各自的一份，节点影响量为各入边之和，且
  不超过其历史接收量（`cap_violations` 必须为 0）。因此两条路径重新汇合也不会把同一来源算两遍。
- **均匀混合 / 来源实测边**按节点历史流出占比拆分；**来源比例未知（`unknown`）的边**不假装能拆分，
  给出下界（其余分支取满后仍剩给它）与上界（最多整份都可能来自问题车）。
- 结果按 **存量 / 已耗用（含损耗）/ 在制（已投炉）/ 已发** 分别汇总。已发、在制、已耗用即
  **无法追回**部分（`unrecoverable_g`）。
- 处置核对：各去向合计与源车接收量对齐（上界按源车接收量封顶），页面显示尾差与是否核对一致，
  每个节点都展示从源车到该节点的**完整路线**及每步承载量。

接口：

```bash
TOK=$(curl -s -X POST localhost:8080/api/login -H 'Content-Type: application/json' \
  -d '{"username":"quality","password":"quality123"}' | jq -r .token)
# 声明质量事件（event_no 幂等：重试返回原事件）
curl -s -X POST localhost:8080/api/quality/events -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' -d @samples/recall/event-risk-range.json
# 生成排查快照（每次一个新 seq）
curl -s -X POST localhost:8080/api/quality/events/1/investigate -H "Authorization: Bearer $TOK"
# 只看最近一次排查
curl -s localhost:8080/api/quality/investigations/1 -H "Authorization: Bearer $TOK"
```

> `samples/recall/event-risk-range.json` 用 `trip_key`（批次号）指定车次；接口也接受 `trip_id`，
> 二者给其一即可，`trip_key` 在服务端按 `trips.batch_no` 解析。

### 隔离处置

1. **申请**（`POST /api/quality/isolation`）：基于某次排查快照生成待批处置单。页面同时展示
   **依赖的当前存量**（将被阻断的批次及其余额）与**正在执行的动作**（已投炉/已发运，不可回滚但要继续追查）。
2. **批准**（`POST /api/quality/isolation/{id}/approve`）：把排查命中的**在库**节点写入阻断
   （`lot_holds`）。批准前若排查之后又发生转移（库存序号变化），**旧排查结论被拒绝**，须重新排查。
   阻断生效后，这些批次的新领料/转移一律 `409`；**已完成的动作保留**，不会回滚成“料还在场”。
3. **复核**（`POST /api/quality/isolation/{id}/review`，可选 `scope_lot_ids`）：
   - 全范围复核（不传 `scope_lot_ids`）释放该处置单全部持有；
   - 只覆盖部分则仅释放这些批次，**剩余继续阻断**；
   - 同一批次被多起事件持有（`unique(event_id, lot_id)` 保证每事件一份），必须**全部事件都复核**才真正放行。
4. **并发与重试**：转移、入库、排查与隔离动作都先取同一条事务级 advisory lock（`rt.stock-world`），
   再按主键顺序 `FOR UPDATE` 锁定批次、读取阻断。因此“读存量→判断→写入”不会交错：排查不会算在
   转移中途，批准也不会插进转移的余额检查与提交之间。要么转移先提交（随后批准因库存序号变化失败），
   要么阻断先提交（随后转移被阻止）。同一事件号重试不会新增持有或重复扩大数量。

## 八、数据模型要点

单位：重量 **g**、金属量 **mg**、比例 **ppm**、金额 **分**（整数运算，无浮点误差）。

- `trips` 稳定批次；`weighings` 每次称次（磅单号唯一）；`weight_adoptions` 采用记录（保留原值+依据，同一车次仅一条 current）。
- `samples` 封样绑定 `(trip_id, position, seal_no)`；`assay_results` 化验版本，质量 `adopt` 才生效。
- `grade_approvals` 等级/隔离/批准；`trip_assay_adoptions` 车次唯一生效化验。
- `inventory_lots` 库存状态节点；`lot_origins` 每个节点的车次级来源构成（重量/金属/占比/依据/尾差）；
  `lot_links` 每对来源→去向的带数量边；`lot_events` 动作时间线。
- `movements` / `transfer_lines` 转移单与明细（`out`/`in`/`loss`，损耗分类 `drying`/`process`）；
  `loss_attribution` 把损耗按车次与类别落到报表。
- `payables` 应付款**版本**（`is_current`/`supersedes_id`，原单永久保留）；`payment_ledger` 调整台账。
- `audit_log` 关键动作留痕。
- `quality_events` 质量事件（具体成分 / 风险范围）；`quality_investigations` 不可变排查快照
  （每事件递增 `seq`，带 `stock_epoch`）；`stock_epoch` 全局库存变更序号；
- `isolation_orders` 隔离处置单；`lot_holds` 批次阻断（`unique(event_id, lot_id)`，事件重试不重复扩大）；
  `isolation_reviews` 复核记录（覆盖全部或部分持有）。

**公式登记**（`internal/num/pricing.go`）：

- `DRY-IMP-METAL`（样例合同）：湿净重 → 扣水 → 干重 → 扣干基单列非金属杂物 → 剩余料 → ×干基金属比例 → ×单价 × 等级系数。
- `WET-NET-METAL`（另一基准）：杂物与金属比例以湿基定义，**单独登记**，不在干基结果上复用比例；
  当化验声明的基准与公式要求不一致时，平台显式换算并记录 `conversions`。

公式每一步的中间量（湿净重、水分、干重、杂物、计价料、金属量、金额）都写入应付快照，
页面可按“一笔扣款 → 净重 → 品位 → 合同计算”逐步展开。
