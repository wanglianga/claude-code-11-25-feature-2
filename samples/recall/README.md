# 排查与隔离样例

本目录演示“某车问题 → 下游排查 → 隔离处置”。与 `transfers/` 不同，这里的样例描述的是
**质量事件**与其下游传播，而不是单张转移单。

## `event-risk-range.json`

描述第四车 `B-20261110-004` 的质量事件：

- `kind`：`risk_range`（风险范围）或 `composition`（具体成分）。风险范围时 `min_ppm` 与
  `max_ppm` 不同，排查结果会给出受影响量的**上下界**；具体成分时视为精确比例。
- `param`：受影响参数，`metal_ppm` / `impurity_ppm` / `moisture_ppm`。
- `trip_key`：车次批次号（对应后端 `trips.batch_no`，导入时换算成 `trip_id`）。

## 故事（由 `cmd/seed` 真实写入数据库）

1. 第四车（问题车）与第五车（好料）**均匀混堆**。
2. 混堆被拆成 **A、B 两支**，两支的**来源分拣记录都不完整**（`mode=unknown`）——
   因此“问题料在某一支里到底占多少”无法精确确定，排查给出下界/上界。
3. A、B 两支各有 3/4 **重新汇合**到一个可用堆：这是一个**菱形（两条路径重新汇合）**。
   简单递归累加会把同一来源在汇合点算两遍；平台按带数量的转移边传播，汇合节点按来源流量归并，
   节点影响量不超过其历史接收量。
4. 汇合堆再拆出 2/5 投炉（**在制**）、3/10 出库（**已发产品**）。
5. 声明质量事件并生成排查快照 `#1`，随后申请隔离单 `ISO-2601-001`。

结果（`rt.quality_investigations`）：

| 去向 | 下界 | 上界 |
| --- | --- | --- |
| 在库存量（可隔离） | 2,850 kg | 8,550 kg |
| 在制（已投炉） | 1,800 kg | 5,400 kg |
| 已发产品 | 1,350 kg | 4,050 kg |
| 已耗用/损耗 | 0 | 0 |
| **合计（≤ 源车接收 18,000 kg）** | **6,000 kg** | **18,000 kg** |

已发与在制合计即“无法追回”的部分；页面按去向分列，不把它们混入可隔离存量。
